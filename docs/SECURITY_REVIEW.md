## 1. 结论摘要

- 没有发现可被外部攻击者直接盗取资金的问题。
- 主要风险来自**权限集中**（多签、暂停人、运营/审核人）和**尚未接入真实 KYC**，这些是设计上的取舍，已写入风险披露。
- 有几项无法在本沙盒里完成的核查（solc 官方校验、BSC 链上地址、测试网），列在 §6。

| 发现 | 来源 | 判定 |
|---|---|---|
| `approveBatch` 从任意地址 `transferFrom` | Slither | 不是问题。来源是部署时固定、不可修改的项目金库地址，且需第二人审批。 |

## 4. 人工审查

### 4.1 权限与治理

- 所有合约管理员是 24 小时时间锁，时间锁只听 2/3 Safe（D-16）。部署脚本在同一交易里核对，部署者不保留任何权限。
- 暂停人可以立即暂停，暂停会同时阻止退款和领取（D-21），恢复需要走 24 小时时间锁。**风险：** 暂停人密钥被盗可冻结资金至少 24 小时，但不能转走资金。建议暂停人也用 Safe。
- 运营提交、审核人批准，合约强制两人不同（项目、报告、分配批次三处），有测试。
- 没有私钥恢复和强制转让功能（D-14），丢失钱包的份额无法找回，已写入风险披露。

### 4.2 资金流

- 认购：用户对 `SubscriptionRouter` 授权 USDT（默认无限授权，D-23）。路由只会从**调用者本人**转到该项目的托管合约，路由不可升级、不留存余额（不变量测试覆盖）。**风险：** 无限授权意味着若路由存在未知漏洞，授权额度内的余额都暴露。DApp 需显示风险提示和撤销按钮（前端线程处理中）。
- 分配：`approveBatch` 从项目金库拉取资金。**建议：** 金库每次只授权本批次金额，不要给分配合约无限授权。
- 余数结转下一批，只有项目关闭后才能清扫（有测试）。
- 收手续费代币被拒绝（实际到账必须等于应付金额）。

### 4.3 合规（KYC）

- 2026-10-09 Charlene 决定暂不接 KYC 服务商。合约里的资格登记与转让限制保留，资格由运营通过 `COMPLIANCE_AGENT` 角色人工设置，**仅用于测试与内部演示，没有任何真实 KYC/AML 审查**。
- 后端 KYC webhook 接口保留但没有对接任何服务商。
- 接入真实 KYC 是公开募集和主网上线的前置条件。

### 4.4 后端

- SIWE 登录：nonce 存 Redis，单次有效；会话为 httpOnly Cookie 中的 HS256 JWT，生产环境要求 ≥32 字节密钥。
- 管理接口：需要员工账号 + 链上对应角色 + 15 分钟内的 TOTP 二次验证；TOTP 密钥用 AES-GCM 加密存储（RFC 6238 测试向量通过）。
- 后端只返回未签名的交易数据，**服务器不持有任何能动用资金的私钥**。
- 限流和幂等键基于 Redis；错误统一格式，不泄露内部信息。
- 索引器只处理已确认区块，能处理链重组，定期与链上状态对账（有测试）。
- Aave 数据只读，每次读取前核对链 ID、合约代码、地址提供者和资产列表。

### 4.5 供应链

- 所有 npm 依赖固定版本，`pnpm install --frozen-lockfile`。
- 新增 CI（`.github/workflows/ci.yml`）：合约测试（含 CI 强度模糊测试）、后端类型检查与测试、`pnpm audit`。CI 中的 GitHub Actions 按版本标签引用，**建议改为固定 commit SHA**（本沙盒无法查询 SHA）。
- OpenZeppelin 5.4.0、forge-std 1.9.7 以 git 子模块固定。
