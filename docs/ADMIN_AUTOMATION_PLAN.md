# 运营自动化与管理后台升级计划

2026-10-11 · 线程「自动化与管理后台升级」· 仅测试网，主网另行审批

目标：日常运营不再需要在 Mac 上开 Claude。能自动的交给后台（worker）自动跑；必须由有权限的钱包签名的，在管理后台一键准备好，用手机钱包签名即可。

原则：服务器不保存任何有合约权限的私钥（只付 gas、没有权限的钱包可以）。要在服务器上放有权限的私钥，必须先由 Charlene 明确同意。

## 现状

后台已有：登记项目、核验、开启募集提案、结算、运营报告提交/审核、分配批次提议/批准、邀请奖励根发布、紧急暂停交易、角色/审计/对账查看。

缺口：
1. 所有治理（Safe 2/3）操作只生成 calldata，要复制到 Safe 网页去签，BSC 测试网的 Safe 网页还不一定支持。
2. 运营/审核/合规/Safe 的私钥都在 Mac 上，手机钱包没有这些角色。

## 一次性准备（需要 Charlene 决定）

要在手机上完成以上操作，测试网的角色要交给她手机里的钱包：
- 给她的钱包授予运营、审核、合规、暂停角色，并登记为后台人员（绑定验证器 App）。
- Safe 3 个 owner 中至少 2 个换成她自己控制的钱包（可以是同一个钱包 App 里的两个账户）。
- 这一步需要最后一次在 Mac 上用现有私钥执行。

注意：分配批次的提议人不能自己批准，所以运营和审核最好是两个不同的钱包账户。

## 第 1 批（正在做）

1. 后台内签 Safe：治理提案存进“待签交易”，owner 在后台点“确认”（链上 approveHash），够 2 人后点“执行”。
2. 首页待办加入待签多签交易。

## 第 2 批（下一步）

重点：每日运营收入录入、每月运营报告与收益分配（与线程「车辆运营期与收益机制」协调）。

## 第 2 批：每月自动分配（已实现，PR 见线程）

流程：每月 2 日（北京时间）起，worker 汇总上个月“每日运营”数据 → 生成运营报告并上链（提交钱包）→ 审核钱包批准报告 → 提交钱包按快照持仓提议分配 → 资金账户 USDT 余额和授权足够后，审核钱包批准，投资者即可领取。

两个服务器钱包（私钥只在 Railway 环境变量里，不进仓库、不进聊天）：
- 提交钱包：AuditRegistry 和各项目 RevenueDistributor 上的 OPERATOR_ROLE。
- 审核钱包：同样两类合约上的 REVIEWER_ROLE。合约禁止自己批准自己，所以必须是两个钱包。

能做：提交/批准运营报告，提议/批准分配批次（以及 OPERATOR_ROLE 自带的 claimFor：替持有人领取到持有人自己地址）。
不能做：改任何合约参数、授予或撤销权限、暂停/恢复、把钱转给持有人以外的地址、动募集款或其他项目资金。
最坏情况：服务器被入侵，有人提交虚假的月报，把资金账户里已授权的 USDT 提前按份额发给真实持有人。防护：单月自动分配上限（AUTOPILOT_MAX_BATCH_USDT，默认 100,000），超限需人工；多签可在后台“自动分配”页一键生成撤销交易；对账有差异时自动暂停。
主网前：列为审计重点，并由 Charlene 重新确认是否全自动。

每月仍需人工的一步：把当月收益 USDT 转入项目资金账户（并一次性授权给分配合约）。余额不足时后台首页会提醒，补足后自动发放。
