# 机器人撮合系统（自动上新车 + 平台补齐）

2026-10-14 · 线程「机器人撮合系统」· Charlene 提出：“会自动创建项目车辆，然后自动补齐份额运营”。
**仅测试网。** 主网要先经过审计、律师确认，并由 Charlene 书面批准。

## 做什么

1. **自动上新车**：在售车辆少于设定数量（默认 1 辆）时，系统取排队中的下一辆车，自动登记、核验，再按多签设定的“上架模板”开放认购。测试网上，如果排队为空，可以自动生成标明“演示车辆”的演示车。
2. **平台补齐**：募集最后 N 小时（默认 1 小时；截止后合约不再接受认购）还没卖完时，平台认购钱包用平台自己的 USDT，通过普通认购入口一次性买下剩余份额。Charlene 2026-10-14 要求网站不提示平台认购份额；只在“投资须知”里写一句“募集截止时如有未售出的份额，平台可能用自有资金认购”（9 种语言）。
3. **投入运营**：满额后，自动结算（已有功能）把募集款转入资金账户。撮合系统随后在后台“多签待签”里生成“投入运营”交易，多签确认后开始计算运营期。投入运营是治理层对车辆真实上路的确认，所以保留人工确认。

## 不做什么

- 募集期间不提前买入来拉高进度；不拆成多个钱包伪装成不同散户。测试网演示车可以模拟买家，并标明“演示车辆”。
- 不从任何投资者钱包扣款。平台钱包只花它自己的余额，和普通投资者一样自己授权、自己认购（D-23 不变）。
- 不承诺收益，不承诺回购。

## 合约改动（ProjectFactory）

- 新增 `LaunchTemplate`，由多签设置：每份价格、最少成立份数、单钱包上限、募集天数、运营期、两次上架最短间隔、收款资金账户、认购条款哈希。
- 新增 `LAUNCHER_ROLE` 和 `launch(projectId, name, symbol)`：对已核验的项目部署合约并按模板开放认购。工厂在同一笔交易里把募集合约的管理员交给多签，自己放弃。
- 上新车钱包**不能**改价格、份数、期限和收款账户，也不能在间隔内连续上架。多签可以随时关闭模板或撤销角色。
- 多签自己也可以调用 `launch`（“每辆车多签确认”模式）。
- 原来的 `deployProject` 不变。新工厂用 `script/DeployLaunchFactory.s.sol` 单独部署，沿用原来的部署器和角色设置，**不需要重新部署其他合约**。

## 服务器钱包

| 钱包 | 权限 | 默认 |
|---|---|---|
| 上新车钱包 | AssetRegistry OPERATOR（登记、设运营期）+ 工厂 LAUNCHER_ROLE（全自动模式） | 复用自动分配提交钱包 |
| 核验钱包 | AssetRegistry REVIEWER（核验；合约要求和登记人不同） | 复用自动分配审核钱包 |
| 平台认购钱包 | 无任何合约权限，持有平台自有 USDT 和 gas | 新建，`BACKSTOP_PRIVATE_KEY` |

私钥只放在 Railway worker 环境变量，不进仓库、不进聊天。

**最坏情况**：服务器被入侵，攻击者可以按模板上架一辆不存在的车。募集款只会进模板里固定的资金账户，攻击者拿不到钱，但投资者可能买到虚假项目（募集失败或多签取消后可全额退款）。平台认购钱包被盗最多损失钱包里的平台 USDT。防护：模板间隔限制、单项目平台认购上限、多签一键关闭。

## 后台

管理后台新增“撮合”页（运营分组）：
- 开关：自动上架、上架方式（全自动 / 每辆车多签确认）、同时在售车辆数、测试网演示车、平台补齐、截止前多少小时补齐、单项目平台认购上限、满额后提醒投入运营。
- 上架模板：填好后一键生成多签交易（同时补齐撮合钱包缺的权限），在“多签待签”确认。
- 待上架车辆：录入名称、网址名、品牌、车型、车辆编号参考（VIN 加盐哈希）。
- 执行记录：每一步上链交易。

## 测试网上线步骤（在 Mac 上，线程「测试网钱包和部署」）

1. `forge script script/DeployLaunchFactory.s.sol --rpc-url $RPC_URL --broadcast`（`OLD_FACTORY=0x32E3…Fa4A`，`SAFE=0xf1f3…3B3D`）。
2. 更新 `deployments/bsc-testnet.json/.env` 和 Railway 的 api、worker：`PROJECT_FACTORY` = 新工厂。
3. 新建平台认购钱包，转入 tBNB，铸造测试 tUSDT；私钥放 Railway worker `BACKSTOP_PRIVATE_KEY`。worker 加 `SAFE`、`SUBSCRIPTION_ROUTER`、`PAYMENT_TOKEN`。
4. 后台“撮合”页：设置模板 → 生成多签交易 → 在“多签待签”确认执行。
5. 打开开关。新项目的收益分配合约仍需在“自动分配”页补授权（后续可改为工厂默认授权）。
